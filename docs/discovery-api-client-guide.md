# Discovery API — руководство для мобильного клиента

Контракт v1, проверен 25 октября 2026 года. Production base URL: `https://api.hunch.trade`.

Это три публичных GET API: авторизация и CSRF не требуются. Они возвращают подготовленные подборки с повторной проверкой текущего рынка, инструмента и котировки. Запросы не создают сделки, позиции или тезисы и не вызывают модели. Для покупки используется существующий торговый API.

Исполняемый источник контракта: [schemas/discovery.ts](../apps/api/src/schemas/discovery.ts). Маршруты: [routes/discovery.ts](../apps/api/src/routes/discovery.ts). Подробности отбора, SQL и проверок: [discovery-api.md](discovery-api.md). Полный генерируемый OpenAPI содержит все три пути; локальный `apps/api/openapi.json` является генерируемым артефактом, а не отдельным вручную поддерживаемым контрактом.

## 1. Разделы

| Endpoint                     | Что означает попадание                                                                                                             | Чего оно не означает                                                                          |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `GET /discovery/quick-wins`  | Близкий срок из данных площадки, высокая цена выбранного исхода, свежая котировка, узкий spread, достаточная известная ликвидность | Гарантированную прибыль, подтверждённое недооценивание или выплату в течение 72 часов         |
| `GET /discovery/smart-money` | Наблюдаемое сохранённое увеличение позиции у минимум двух квалифицированных групп владельцев                                       | Подтверждённую покупку, независимость всех неизвестных связей между владельцами или консенсус |
| `GET /discovery/hidden-gems` | Свежий публично одобренный направленный holder research                                                                            | Доказанный edge, низкую цену или сохранение привлекательности входа после изменения цены      |

`quick-wins`, `smart-money`, `hidden-gems` — типы подборок. `sports`, `politics`, `crypto` и другие значения `market.category` — тематики рынка. Это разные измерения.

## 2. Параметры запроса

| Параметр       | Тип / default                                      | Семантика                                                                                                                                                     |
| -------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `limit`        | Целое 1–50, default `20`                           | Максимум карточек на странице, а не размер всей подборки                                                                                                      |
| `cursor`       | Непрозрачная строка, максимум 2048 символов        | Передавать полученный `nextCursor` без декодирования или изменений                                                                                            |
| `q`            | Строка, до 100 символов                            | Все нормализованные слова должны находиться в названии события, рынка или выбранного исхода; без перевода и semantic search                                   |
| `categories`   | CSV, например `politics,crypto`                    | OR между указанными тематиками; AND с другими фильтрами. Нижний регистр, буквы/цифры/`_`/`-`; неизвестная корректно записанная тематика даёт пустой результат |
| `venues`       | CSV: `polymarket`, `limitless`, `kalshi`           | Пример: `polymarket,limitless`. Фактическая доступность площадки дополнительно проверяется сервером                                                           |
| `withResearch` | Строка `true` или `false`, default `false`         | Для Quick Wins / Smart Money: только рынки с текущим подходящим публичным research; для Hidden Gems условие уже обязательно                                   |
| `horizonHours` | Только Quick Wins: `24`, `72`, `168`; default `72` | Горизонт по исходному сроку рынка, не по гарантированному времени расчёта                                                                                     |

Не передавать `horizonHours` в другие разделы. Неизвестные query-параметры не поддерживаются и отклоняются. CSV не является JSON-массивом; для `venues` не добавлять пробелы между значениями. Пустые необязательные списки лучше не отправлять.

Поиск и фильтры применяются внутри подборки, а не ко всему каталогу Hunch. Отсутствие рынка в выдаче не означает, что его нет в Hunch. Фильтрация выполняется до выбора одного представительного рынка на событие: с `withResearch=true` представитель события может отличаться от выдачи без этого фильтра.

### Примеры curl

```sh
# Все Quick Wins на ближайшие 72 часа, первая страница.
curl --fail-with-body --silent --show-error --get \
  'https://api.hunch.trade/discovery/quick-wins' \
  --data-urlencode 'limit=20' \
  --data-urlencode 'horizonHours=72'

# Более широкий горизонт; тема и поиск применяются к подборке.
curl --fail-with-body --silent --show-error --get \
  'https://api.hunch.trade/discovery/quick-wins' \
  --data-urlencode 'horizonHours=168' \
  --data-urlencode 'categories=politics' \
  --data-urlencode 'q=Israel'

curl --fail-with-body --silent --show-error --get \
  'https://api.hunch.trade/discovery/smart-money' \
  --data-urlencode 'venues=polymarket' \
  --data-urlencode 'withResearch=true'

curl --fail-with-body --silent --show-error --get \
  'https://api.hunch.trade/discovery/hidden-gems' \
  --data-urlencode 'limit=50' \
  --data-urlencode 'categories=politics'

# На следующей странице повторить исходные фильтры.
# REPLACE_WITH_NEXT_CURSOR — placeholder, не настоящий cursor.
curl --fail-with-body --silent --show-error --get \
  'https://api.hunch.trade/discovery/quick-wins' \
  --data-urlencode 'limit=20' \
  --data-urlencode 'horizonHours=72' \
  --data-urlencode 'cursor=REPLACE_WITH_NEXT_CURSOR'
```

## 3. Оболочка ответа и пагинация

| Поле                              | Тип                 | Использование                                                                                |
| --------------------------------- | ------------------- | -------------------------------------------------------------------------------------------- |
| `section`                         | Enum трёх разделов  | Проверить соответствие выбранному разделу                                                    |
| `items`                           | Массив карточек     | Может содержать меньше `limit`, включая ноль                                                 |
| `nextCursor`                      | `string` или `null` | `null` означает конец; непустой cursor означает возможность продолжения                      |
| `snapshotId`                      | UUID                | Версия подготовленной подборки                                                               |
| `generatedAt`                     | ISO 8601 UTC        | Время формирования версии                                                                    |
| `freshness.status`                | `fresh` / `stale`   | Состояние подготовленной версии, отдельно от котировок                                       |
| `freshness.sourceAsOf`            | ISO 8601 UTC        | Момент, к которому относится подготовленная основа подборки                                  |
| `freshness.projectionRefreshedAt` | ISO 8601 или `null` | Последняя успешная проверка activity projection у Quick Wins                                 |
| `freshness.quoteMaxAgeSeconds`    | `300`               | Предел свежести котировки; время конкретной котировки — `quote.asOf`                         |
| `freshness.warnings`              | `string[]`          | Пояснения/ограничения; это не ошибки запроса                                                 |
| `page.scannedCandidates`          | Целое               | Число проверенных кандидатов в этом запросе, не общее число карточек                         |
| `page.scanBudgetReached`          | Boolean             | Работа остановлена по бюджету проверки до заполнения страницы; при наличии cursor продолжить |

У ответа **нет `total`, `offset` или `pageNumber`**. Размер результата не фиксирован: 12 карточек в одном срезе не означает ограничение «не больше 12».

Обход:

1. Запросить первую страницу с выбранными фильтрами.
2. Добавить `items`, сохранить `nextCursor` вместе с фильтрами и `snapshotId`.
3. При следующей загрузке передать cursor и те же фильтры. Менять `limit` разрешено.
4. Закончить только при `nextCursor === null`. Пустая или короткая страница с cursor не является концом.
5. При смене раздела, поиска, темы, площадки, горизонта или `withResearch` начать новый обход без cursor. Не смешивать ответы старого и нового запроса в клиентском кеше.

Версия живёт 15 минут; порядок внутри неё фиксирован, но инструмент, доступность и котировки перепроверяются при чтении. Закрывшиеся рынки и отозванные research могут исчезнуть между запросами. Для pull-to-refresh удалить старый cursor и заменить список первой страницей новой версии. Защитная дедупликация по `item.id` полезна для сетевых повторов; сервер группирует представителей по `market.eventId`.

Один спортивный матч может иметь несколько отдельных `eventId` площадки: основной исход, точный счёт, дополнительные рынки. Дедупликация по `eventId` **не объединяет их в один реальный матч**. Разделы также могут пересекаться между собой.

## 4. Карточка и правильное отображение

Все цены и денежные метрики — **десятичные строки**, не JSON numbers. Отсутствующее значение — `null`, не ноль. Для денежных вычислений использовать десятичную арифметику; дату отображать в часовом поясе пользователя.

| Блок          | Поля                                              | Что показывать / учитывать                                                                                     |
| ------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Идентичность  | `id`, `market.marketId`, `market.eventId`         | `id` — идентификатор карточки; market/event IDs — для существующих экранов                                     |
| Название      | `market.eventTitle`, `market.title`               | Оба уровня: не показывать «30–34» или «October 31» без события                                                 |
| Классификация | `market.category`, `market.venue`, `market.image` | Тематика/изображение могут быть `null`                                                                         |
| Условия       | `market.resolutionCondition`                      | Полный текст условий; доступен в раскрываемом блоке                                                            |
| Выбор         | `selection.side`, `selection.outcomeLabel`        | Каноническая сторона YES/NO и пользовательское название исхода                                                 |
| Инструмент    | `selection.instrument`                            | `marketId`, `venue`, `tokenId`, `outcome`, `generation`, nullable `expiry`; весь объект тоже может быть `null` |
| Цена          | `quote.status`, `bid`, `ask`, `midpoint`, `asOf`  | Статус `fresh`, `stale` или `unavailable`; числа/дата могут быть `null`                                        |
| Сроки         | `timing.marketEndAt`, `closeAt`, `eventEndAt`     | Исходные сроки площадки; не заменять ими время выплаты                                                         |
| Смысл срока   | `timing.basis`, `settlementAt`                    | Basis — `venue_market_expiration_not_guaranteed_settlement`; `settlementAt` в v1 всегда `null`                 |
| Действие      | `copyAvailable`                                   | Можно ли предлагать переход в существующий торговый ticket; не подтверждение исполнимости сделки               |
| Аналитика     | `research`                                        | Nullable публичная публикация, отдельные дата, цена и сторона                                                  |
| Объяснение    | `reason`                                          | Discriminated union по `reason.kind`, см. ниже                                                                 |

У YES/NO нет универсального смысла «за событие / против события». Например, YES для «No Hormuz Agreement» означает отсутствие соглашения; NO для того же рынка — противоположный исход. В спортивном рынке NO может называться Thunder или Under. Не определять сторону по заголовку или цвету; использовать `side` вместе с `outcomeLabel` и точными условиями.

### Публичный research

`research` содержит `noteId`, `createdAt`, `headline`, `summary`, `side`, `strength` (`strong`/`good`), `researchedPrice`, `researchedAt`, `sources`, `caveats` и nullable `instrument` той же формы, что у выбранной стороны.

Каждый источник: `id`, `headline`, `url`, nullable `publishedAt`. Пустой массив `sources` допустим: публикация может опираться на наблюдаемое позиционирование без внешних статей. Это не означает, что клиент должен рисовать несуществующие ссылки. Текст выводить как текст, не исполнять как HTML; URL открывать обычным безопасным механизмом клиента.

**`withResearch=true` не означает, что research поддерживает выбранную сторону.** В Quick Wins / Smart Money сравнивать `research.side` с `selection.side`; при несовпадении показывать «Противоположный взгляд». Цена research относится к его стороне и его времени. Нельзя сравнивать её с ask противоположной стороны как движение одной и той же позиции. В Hidden Gems выбранная сторона соответствует публикации.

Даже при совпадении стороны сравнение цен требует того же инструмента/поколения. Не брать `tokenId` из research для покупки выбранной Discovery-карточки. Торговый API должен заново подтвердить актуальный инструмент и исполнимую цену.

## 5. Объяснения по разделам

### Quick Wins

Проверяются обе стороны. Обязательны активность, разрешение на новые покупки, текущий инструмент, условия расчёта, ненулевой валидный объём за 24 часа и известная ликвидность от $1 000. Midpoint и ask выбранной стороны — **0.85–0.95 включительно**; spread — не больше 0.03; котировка — не старше пяти минут и без пересечения bid/ask. Разрешённые, предложенные к расчёту и спорные исходы исключаются.

Сортировка: ближайший срок → меньший spread → большая ликвидность → стабильный ID. Применяется один представитель на событие после фильтров.

`reason`:

- `kind: "quick-wins"`;
- `volume24hUsd`, `liquidityUsd` — decimal strings;
- `grossReturnIfWin` — `1 / ask - 1`, десятичная доля: `0.05` означает 5%;
- `returnBasis: "top_ask_excludes_depth_fees_slippage"`;
- `resolutionClarity: "rules_provided_not_human_reviewed"`.

UI-подпись: «Валовой возврат при выигрыше, без комиссий и проскальзывания». Не «ожидаемая доходность», не «гарантированный доход». Близкий `marketEndAt` не доказывает скорый settlement: в правилах может быть более поздний дедлайн. Наличие правил не равно ручной проверке их ясности.

Для макета: множитель выплаты `1 / ask`, валовая выплата на условные $100 — `100 / ask`, прибыль при выигрыше — `100 / ask - 100`. Выплата включает исходные $100. Считать десятичной арифметикой. При ask 90¢ это примерно 1,1111× / $111,11 / $11,11 до расходов. Кнопка использует `selection.side` и `outcomeLabel`, не жёсткий `Buy Yes`. Signal необязателен: без `research` блок скрывается.

Диапазон даёт примерно 5,26–17,65% валового возврата **при выигрыше**, до расходов. Это ценовой фильтр, а не наша оценка вероятности победы 85–95% и не гарантированная чистая доходность. Более низкая цена означает также больший рыночно подразумеваемый риск проигрыша; реальные комиссии проверяются в торговом API.

### Smart Money

Квалификация: активность кошелька в пределах семи дней, метрики не старше суток, положительные приблизительные 30-дневные PnL и historical edge, минимум 20 разрешённых наблюдений, исключение предполагаемых маркетмейкеров. Известные связанные владельцы объединяются; существенные противоположные позиции исключают поддержку владельца.

Учитывается полное 24-часовое окно `snapshot_delta`: BUY прибавляет, SELL вычитает абсолютные доли. Сохранившееся увеличение подтверждается достаточно свежей текущей позицией. Текущая позиция и оценка сохранённого увеличения должны достигать $100; нужно минимум две квалифицированные группы владельцев. Сделки не прибавляются вторично к изменениям снимков.

`reason`:

- `kind: "smart-money"`, `evidenceBasis: "observed_snapshot_increase"`, `windowHours: 24`;
- `ownerGroups`, `oppositeOwnerGroups` — число поддерживающих групп на каждой стороне;
- `observedIncreaseValueUsd` — оценка сохранившегося увеличения, не фактические потраченные доллары;
- `observedAt` — время наблюдения;
- `opposingViews` — есть поддержка противоположной стороны;
- `traders` — до трёх публичных представителей: `walletId`, nullable `displayName`, `pnl30dUsd`, `pnlIsApproximate: true`, `resolvedObservations30d`, `edge30d`, `metricsAsOf`.

Сортировка: число групп → оценка увеличения → стабильный ID. Показывать обе стороны и формулировку «Наблюдаемое увеличение позиции». 12 групп против 10 — не консенсус; положительный прошлый PnL не является вероятностью выигрыша рынка. В v1 нет сортировки по степени согласия или квот тематического разнообразия.

#### Новые поля карточки Smart Money

Опциональный `reason.positioning` содержит:

- `selected` / `opposite`: `side`, `ownerGroups`, `walletCount`, `positionValueUsd`, `observedIncreaseValueUsd`;
- `selectedIncreaseShare`: десятичная доля выбранной стороны в суммарном наблюдаемом увеличении; `"0.82"` → «82% наблюдаемого увеличения», **не 82% вероятности победы**;
- `oldestSnapshotAt`, `latestSnapshotAt`, `windowHours: 24`, `basis: qualified_owner_groups_with_retained_snapshot_increase`.

Все числа — из одной Discovery-когорты после объединения владельцев и исключения существенного хеджирования. `walletCount` включает кошельки с положительной позицией внутри допущенных групп, в том числе известные связанные кошельки; нельзя подписывать это как число независимо прибыльных трейдеров. Для такой подписи использовать число квалифицированных **групп**. PnL и edge в представителе относятся только к нему, не к сумме выборок связанных кошельков. Не подмешивать данные из legacy wallet-positioning API. Signal здесь тоже необязателен.

#### See Traders — полный список

```http
GET /discovery/smart-money/polymarket%3A682705/traders?snapshotId=<snapshotId>&side=NO&limit=20
```

Передавать `snapshotId` родительской подборки и `selection.side` карточки. `side` опционален, но без него выбирается первый представитель рынка в сохранённом порядке; явная сторона исключает неоднозначность. `limit` — 1–50, по умолчанию 20. Следующие страницы: те же snapshot/market/side плюс полученный `cursor`; это отдельный cursor, не cursor общей подборки.

Ответ: `snapshotId`, `marketId`, `selectedSide`, `generatedAt`, неизменный `positioning`, `items`, `nextCursor`. Одна запись `items` — группа владельца: непрозрачный `groupId`, `side`, `walletCount`, `positionValueUsd`, `observedIncreaseValueUsd`, даты снимков/наблюдения и `representative` с существующими публичными полями трейдера. Внутренних связей аккаунтов и адресов участников нет.

Сначала идут группы выбранной стороны, затем противоположной; внутри — по увеличению и стабильному ID. В отличие от прежнего `reason.traders` (до трёх представителей), здесь доступен весь список на обеих сторонах. По истечении 15 минут — 409: перечитать карточку и открыть её новый snapshot. Закрытый рынок/сменившийся инструмент/выключенная площадка — 404. Если старая версия не содержит полных групп — 503; дождаться фоновой пересборки и взять новый snapshot, не повторять бесконечно старый. Устаревшая цена сама по себе не мешает прочитать датированный список групп; он не является торговой котировкой.

### Hidden Gems

Только `holder_research`, тип `signal`, статус `active`, публичный quality-gate `PUBLISH`, возраст не больше семи дней. Используется актуальная действующая публичная публикация по рынку. Map signals её не заменяют.

`reason`: `kind: "hidden-gems"`, `strength: "strong" | "good"`, `basis: "public_approved_research_not_proven_mispricing"`.

Сортировка: strong → good → свежесть → стабильный ID. Показать тезис, его дату, источники, оговорки, цену исследования и текущую цену раздельно. Одобрение публикации не доказывает актуальную недооценённость; v1 не убирает идею только потому, что цена после публикации значительно изменилась.

При устаревшей котировке research остаётся читаемым, текущие `bid`/`ask`/`midpoint` становятся `null`, а `copyAvailable` — `false`. При несовпадении research-инструмента с текущим котировка помечается `unavailable` и Copy также выключается. Не превращать `null` в цену 0. Отозванная либо заменённая публикация исчезает из текущего обхода.

#### Экспериментальная оценка и потенциал

На уровне карточки добавлены опциональный `estimate` и nullable `valuation`. Это эвристика `research-odds-v1`, `version: 1`, **`calibrated: false`**. Подпись для пользователя: **«Экспериментальная оценка»**. Не «истинная вероятность», не «прогноз с доказанной точностью».

| UI                           | API                                 | Отображение                                                          |
| ---------------------------- | ----------------------------------- | -------------------------------------------------------------------- |
| Рыночная цена / вероятность  | `quote.midpoint`                    | Доля × 100%; относится к выбранной стороне                           |
| Экспериментальная оценка     | `estimate.probability`              | Доля × 100%, разумное округление без ложной точности                 |
| Расхождение с рынком         | `valuation.probabilityDifferencePp` | Уже в процентных пунктах: `"5"` → +5 п.п.                            |
| Потенциал по оценке          | `valuation.modelUpsideRatio`        | Доля × 100%; сохранять минус; до комиссий, глубины и проскальзывания |
| Валовая прибыль при выигрыше | `valuation.grossReturnIfWin`        | Отдельная условная величина, не модельный потенциал                  |

Формулы: расхождение `100 × (оценка − midpoint)`, потенциал `оценка / ask − 1`, прибыль при выигрыше `1 / ask − 1`. При оценке 55%, midpoint 50% и ask 51¢ это +5 п.п., около +7,84% и +96,08% соответственно — три разных показателя. Потенциал не означает обещанный рост цены.

`estimate.status`:

- `available`: есть ненулевая экспериментальная поправка;
- `market_only`: поправка нулевая; число совпадает с midpoint, это не независимое подтверждение рынка;
- `unavailable`: скрыть численную оценку/потенциал, показать подходящее объяснение из `reason`; research продолжает читаться.

`reason` уточняет проблему: нет/устарели метрики или позиция, неподтверждённый инструмент, другая сторона, нет свежей котировки либо отсутствуют входные данные старой версии. Не заменять отсутствующее число нулём. `representativeWalletId`, `sampleSize`, `researchAsOf`, `metricsAsOf`, `positionAsOf`, `quoteAsOf`, `calculatedAt`, `coverage` и `warnings` доступны для раскрываемого объяснения. `coverage: representative_only` означает неполное покрытие противоположной поддержки, не консенсус.

Исторический результат выбранного в research трейдера сглаживается к его исторической рыночной базе (50 условных наблюдений), переводится в поправку к логарифму шансов (ограничение 2×), ослабляется возрастом research (полураспад семь дней) и сохранённой противоположной поддержкой. Это явно заданные эвристики, не обученные коэффициенты. [Полная формула и ограничения](discovery-api.md#experimental-estimate-research-odds-v1).

Расчёт заново использует **текущие** midpoint/ask той же стороны/поколения при чтении карточки. Старое research по 69¢ не может дать фиктивный огромный потенциал относительно нового ask 2¢. Отрицательная оценка потенциала допустима и не исключает исследование из подборки. Опубликованный research, его историческая цена и нынешняя оценка — разные сущности.

#### Источники и краткий контекст

Внутри `research` доступны опциональные `sourceCount`, `contextHighlight` и `evidenceMetrics`:

- `sourceCount` — фактическое количество публичных источников; ноль допустим.
- `contextHighlight` — nullable `{kind: "news", sourceId, headline, url, publishedAt}` из уже доступного источника. Дата публикации — **не дата будущего катализатора**. Нет источника — нет блока новости.
- `evidenceMetrics` — только безопасные типизированные метрики: вид/область, scalar/range измерение с единицей, период `horizonDays`, выборка `sampleSize`, дата `asOf`, публичный `sourceId` при наличии. Это сохранённые сведения research, не текущая рыночная вероятность. Их выборки нельзя суммировать как независимых трейдеров.

«Read research» открывает существующий `/hunches/:noteId`; не обещать длинную статью, которой нет. Summary, caveats и sources остаются прежними. Колокольчик подписки и календарь этим патчем не добавлены. Старые клиенты могут игнорировать новые поля; новые должны терпеть их отсутствие в старых версиях.

## 6. Ошибки, свежесть и клиентский кеш

| HTTP / code                                    | Действие клиента                                                                         |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `200`, пустые `items`, `nextCursor: null`      | Честное пустое состояние для этих фильтров                                               |
| `200`, пустые/короткие `items`, cursor не null | Разрешить продолжение; не показывать «больше ничего нет»                                 |
| `400`, ошибка query validation                 | Исправить параметры; тело содержит `error`, поле `code` необязательно                    |
| `400 discovery_invalid_cursor`                 | Перезапустить обход с согласованными фильтрами                                           |
| `404 discovery_market_not_found`               | Список трейдеров недоступен для рынка/стороны; обновить родительскую карточку            |
| `409 discovery_cursor_expired`                 | Версия истекла: сбросить cursor и обновить список, не дописывать новый snapshot в старый |
| `503 discovery_unavailable`                    | Показать временную недоступность, а не пустую подборку; соблюдать `Retry-After: 15`      |

Quick Wins и Hidden Gems обновляются примерно раз в минуту; Smart Money — раз в пять минут. Базовый пул Quick Wins обновляется раз в пять минут. При ошибке остаётся последняя полная версия: не старше пяти минут для Quick Wins / Hidden Gems и 15 минут для Smart Money. `freshness.status: stale` нужно показывать явно. При слишком старой версии или холодном старте сервер отвечает 503 и выполняет фоновую попытку обновления.

Пятнадцатиминутная жизнь cursor не делает цены неизменными и не гарантирует доступность старого обхода при недоступности свежей основы. Клиент не должен выполнять плотный автоматический цикл при 503. HTTP-ответы имеют `Cache-Control: no-store`; если UI временно держит уже показанные карточки в памяти, не выдавать их котировки за заново подтверждённые и не использовать их как order quote.

## 7. Что проверять при интеграции

При чтении Discovery API асинхронно помечает текущие токены обеих сторон проверенных рынков как hot и ставит их в общую очередь обновления цен, как feed. Фоновая сборка также запрашивает отсутствующие/устаревшие котировки кандидатов, даже если они ещё не вошли в выдачу; весь исходный пул hot не становится. Используются штатные ограничения очереди, без прямого запроса к площадке из HTTP-обработчика. Ответ не ждёт обновления. Запрос refresh не превращает старую цену в свежую: критерий пяти минут остаётся, а восстановленный кандидат может появиться в следующей сборке. Текущий cursor сохраняет прежний список кандидатов; для нового списка нужен новый обход.

- Все три раздела, тематические фильтры и пустые результаты.
- Первую, следующую и последнюю страницы; короткую/пустую страницу с cursor.
- Смену фильтра и pull-to-refresh без смешивания snapshot.
- YES/NO на отрицательном заголовке и именованный спортивный исход.
- Research противоположной стороны; пустые источники; отдельные цены и даты.
- Stale/unavailable котировку с выключенным Copy и читаемым research.
- `available` / `market_only` / `unavailable`, отрицательный потенциал, отдельные единицы п.п. и процентов.
- Полные страницы трейдеров обеих сторон и согласованность их сумм с карточкой в одном snapshot.
- Отсутствующие необязательные поля старых версий, ноль источников и дата новости без вымышленного катализатора.
- Ошибки 400/409/503 и `Retry-After`, без бесконечных немедленных повторов.
- Переход в существующий ticket с новой проверкой цены, без исполнения сделки из данных Discovery.

Read-only проверка production 25 октября 2026 около 18:47 UTC на прежнем диапазоне 0.90–0.98 дала 8 / 12 / 24 Quick Wins на горизонтах 24 / 72 / 168 часов, 35 Smart Money и 18 Hidden Gems. Cursor-проверки в том же временном окне прошли как 20+4, 20+15 и 10+8 без повторяющихся `eventId` и без смены версии внутри обхода. На этом срезе все карточки были Polymarket.

Отдельное сравнение всего исходного пула из 770 рынков в 19:03 UTC на одинаковых котировках дало для старого диапазона 6 / 10 / 22 события, для нового 0.85–0.95 — 6 / 11 / 20. Это датированные примеры, **не лимиты и не гарантированный состав**. Отсутствие данных другой площадки не компенсируется фиктивной ликвидностью или обычными сигналами. Детали сравнения и оставшиеся ограничения — в [основном контракте](discovery-api.md#price-band-validation-on-25-october-2026).
